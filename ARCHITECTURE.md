## 1. Compilation pipeline

```
Source file (.ml)
        │
        ▼
┌───────────────┐
│  CharStream   │  ← file read as a character stream
└───────────────┘
        │
        ▼
┌───────────────┐
│ MyLangLexer   │  ← tokenization: characters → tokens (INT, ID, 'print', ...)
│   (ANTLR4)    │    lexical errors → ErrorListener
└───────────────┘
        │ CommonTokenStream
        ▼
┌───────────────┐
│ MyLangParser  │  ← parsing: tokens → parse tree
│   (ANTLR4)    │    syntax errors → ErrorListener
└───────────────┘
        │ ParseTree
        ▼
┌───────────────┐
│  LLVMActions  │  ← visitor: walks the tree, checks types, builds IR
│  (visitor)    │    semantic errors → stderr
└───────────────┘
        │ LLVMGenerator.main_text / header_text
        ▼
┌───────────────┐
│LLVMGenerator  │  ← assembles a complete LLVM IR module as text
│  .generate()  │
└───────────────┘
        │
        ▼
  stdout: LLVM IR (.ll)
        │
        ▼  (outside the compiler)
  lli / clang → execution
```

## 3. Lexical analysis (lexer)

ANTLR4 generates `MyLangLexer` from the token definitions in `MyLang.g4`.
The lexer follows the **maximal munch** rule: it always matches the longest possible token.

### Key tokenization rules

| Token       | Pattern              | Example     | Note                                         |
|-------------|----------------------|-------------|----------------------------------------------|
| `DOTDOT`    | `'..'`               | `1..5`      | Must come before `REAL`, otherwise `1.` is a REAL |
| `REAL`      | `[0-9]+ '.' [0-9]+`  | `3.14`      | Requires digits after the dot                 |
| `INT`       | `[0-9]+`             | `42`        | After `REAL` – munch picks REAL for `3.14`    |
| `EQ`        | `'=='`               | `==`        | Before `'='`, otherwise `==` becomes two `=`  |
| `LE`        | `'<='`               | `<=`        | Before `'<'`                                  |
| `WS`        | `[ \t]+`             | (spaces)    | Skipped                                       |
| `NEWLINE`   | `'\r'? '\n'`         | end of line | NOT skipped – used as a statement separator   |

### Tokenization example

```
int[1..5] arr
```
Tokens: `ID("int")`, `'['`, `INT(1)`, `DOTDOT(..)`, `INT(5)`, `']'`, `ID(arr)`, `NEWLINE`

## 4. Parsing (parser)

The parser builds a **parse tree** according to `MyLang.g4`.
The rule hierarchy encodes operator precedence.

### Expression hierarchy (lowest to highest precedence)

```
expr
  └─ orExpr          (OR)
       └─ xorExpr    (XOR)
            └─ andExpr    (AND)
                 └─ notExpr    (NOT)
                      └─ cmpExpr    (==, !=, <, >, <=, >=)
                           └─ addExpr    (+, -)
                                └─ mulExpr    (*, /)
                                     └─ castExpr    ( (type) )
                                          └─ unaryExpr    (-)
                                               └─ primaryExpr    (literals, ID, arr[i], s.field, calls)
```

Example: `a + b * 2 > 5 AND flag`

```
andExpr
  ├─ cmpExpr (>)
  │    ├─ addExpr (+)
  │    │    ├─ mulExpr → a
  │    │    └─ mulExpr (*)
  │    │         ├─ castExpr → b
  │    │         └─ castExpr → 2
  │    └─ addExpr → 5
  └─ notExpr → flag
```

### Labeled ANTLR4 alternatives

The `#alternativeName` syntax makes ANTLR generate a separate `visitXxx`
method for every label:

```antlr
addExpr
    : addExpr '+' mulExpr  #addOp   → visitAddOp(AddOpContext ctx)
    | addExpr '-' mulExpr  #subOp   → visitSubOp(SubOpContext ctx)
    | mulExpr               #addPass → visitAddPass(AddPassContext ctx)
    ;
```

This lets `LLVMActions` handle every operator independently,
without checking `ctx.op.getType()`.

## 5. Semantic analysis (LLVMActions)

`LLVMActions` extends `MyLangBaseVisitor<Value>` and implements the semantic
checks and code generation for every tree node.

### Symbol table

```java
Map<String, VarType>   variables;  // name → type for scalars
Map<String, ArrayInfo> arrays;     // name → ArrayInfo for arrays
```

Functions and struct/class bodies get their own scope, so local variables
do not leak into the global one.

For the declaration `int x = 5`:
1. Check that `x` is not already declared
2. Add it to `variables`: `{"x" → INT}`
3. Call `LLVMGenerator.declare("x", INT)` → emits `%x = alloca i32`
4. Visit the expression `5` → `Value("5", INT)`
5. Call `LLVMGenerator.assign("x", "5", INT)` → emits `store i32 5, i32* %x`

### Expression evaluation pattern

Every expression visitor returns a `Value(register, type)`:

```
visit(addExpr: a + b)
  → Value leftVal  = visit(a)    → Value("%1", INT)
  → Value rightVal = visit(b)    → Value("%2", INT)
  → unifyNumeric(left, right)    → no conversion (both INT)
  → LLVMGenerator.add("%1","%2", INT) → emits "%3 = add i32 %1, %2"
  → return Value("%3", INT)
```

### Type unification (unifyNumeric)

In binary operations the narrower type is promoted to the wider one:

```
(INT, FLOAT32)   → (FLOAT32, FLOAT32)    sitofp i32 → float
(INT, REAL)      → (REAL, REAL)          sitofp i32 → double
(FLOAT32, REAL)  → (REAL, REAL)          fpext float → double
(REAL, FLOAT64)  → (REAL, REAL)          both are double – no conversion
```

## 6. IR generation (LLVMGenerator)

`LLVMGenerator` accumulates code in two text buffers and assembles them into
a complete LLVM IR module in `generate()`.

### Building the IR

```
header_text += "@strlit_1 = constant [6 x i8] c\"hello\00\"\n"
main_text   += "  %1 = alloca i32\n"
main_text   += "  store i32 5, i32* %1\n"
...
generate() → joins all parts into a single .ll file
```

### Register numbering (SSA)

LLVM requires every value-producing instruction to have a unique number:

```llvm
%1 = alloca i32
%2 = load i32, i32* %1
%3 = add i32 %2, 5
%4 = call i32 @printf(...)
```

No register may be skipped – even the result of a `call` whose value is never
used MUST get a number. Hence the pattern:

```java
String r = nextReg();
main_text += "  " + r + " = call i32 @printf(...)\n";
```

### Format strings

Global constants shared by all I/O operations:

| Constant       | Value          | Used for               |
|----------------|----------------|------------------------|
| `@fmt_i32_p`   | `"%d\n\0"`     | printf int             |
| `@fmt_f64_p`   | `"%f\n\0"`     | printf double/float    |
| `@fmt_str_p`   | `"%s\n\0"`     | printf string          |
| `@fmt_i32_r`   | `"%d\0"`       | scanf int/bool         |
| `@fmt_f64_r`   | `"%lf\0"`      | scanf double           |
| `@fmt_f32_r`   | `"%f\0"`       | scanf float            |
| `@fmt_str_r`   | `"%255s\0"`    | scanf string (255 max) |

## 7. Type system and conversions

### Type mapping

```
MyLang   │ LLVM IR │ Size    │ Note
─────────┼─────────┼─────────┼──────────────────────────────
int      │ i32     │ 32 bit  │ signed, division = sdiv
real     │ double  │ 64 bit  │ alias of float64
float32  │ float   │ 32 bit  │ ~7 significant digits
float64  │ double  │ 64 bit  │ ~15 significant digits
bool     │ i1      │ 1 bit   │ true=1, false=0
string   │ i8*     │ pointer │ 256-byte buffer on the stack
```

### Explicit (cast) and implicit (coerce) conversions

```
        int ──────────────────────────────────────────┐
         │  sitofp i32→float         sitofp i32→double│
         ▼                                            ▼
      float32 ──────────────────────────────────── double
         │  fpext float→double                        │
         └────────────────────────────────────────────┘
                      fptrunc double→float

  int ←→ bool:   icmp ne i32 v, 0   /   zext i1 v to i32
float ←→ bool:   fcmp une f v, 0.0  /   sitofp after zext
  int  →  float: sitofp i32 v to float/double
float  →  int:   fptosi float/double v to i32 (truncation)
```

### printf promotion (C ABI)

The C ABI promotes `float` to `double` when passing it to a variadic function:
```java
// a float cannot be passed to printf directly
String ext = floatToDouble(val);       // fpext float val to double
main_text += "... @printf(@fmt_f64_p, double " + ext + ")\n";
```

## 8. Short-circuit evaluation

AND and OR are compiled to conditional branches and phi nodes instead of plain logical instructions.

### AND (b1 AND b2)

If `b1 = false`, the result is `false` and `b2` is never evaluated.

```llvm
; [current block] – evaluate b1
%1 = load i1, i1* %a
br i1 %1, label %and_eval_0, label %and_false_0

and_eval_0:              ; b1 = true → evaluate b2
  %2 = load i1, i1* %b
  br label %and_end_0

and_false_0:             ; b1 = false → result = false (b2 skipped)
  br label %and_end_0

and_end_0:
  %3 = phi i1 [%2, %and_eval_0], [false, %and_false_0]
  ; %3 = a AND b
```

### OR (b1 OR b2)

If `b1 = true`, the result is `true` and `b2` is never evaluated.

```llvm
; [current block] – evaluate b1
%1 = load i1, i1* %a
br i1 %1, label %or_true_0, label %or_eval_0

or_eval_0:               ; b1 = false → evaluate b2
  %2 = load i1, i1* %b
  br label %or_end_0

or_true_0:               ; b1 = true → result = true (b2 skipped)
  br label %or_end_0

or_end_0:
  %3 = phi i1 [%2, %or_eval_0], [true, %or_true_0]
  ; %3 = a OR b
```

### The phi node

`phi i1 [v1, %l1], [v2, %l2]` picks a value depending on which block control
came from. The compiler tracks `currentBlock` (the active basic block) so the
phi node knows which label to attach to `v1`.

## 9. Arrays with index ranges and strings

### Declaration

```
MyLang:   int[5] arr          →  %arr = alloca [5 x i32]
MyLang:   int[1..3] ranged    →  %ranged = alloca [3 x i32]
```

Whatever range the user declares, LLVM always indexes from 0.
The range metadata is kept in `ArrayInfo`.

### Index adjustment

For `int[1..3] ranged` the user writes indices 1, 2, 3.
Before the GEP the compiler adjusts the index: `adjusted = user_index - startIndex`.

```llvm
; ranged[2] = 200
; user_index = 2, startIndex = 1
%idx = ... (value 2)
%adj = sub i32 %idx, 1      ; adjusted = 2 - 1 = 1
%gep = getelementptr inbounds [3 x i32], [3 x i32]* %ranged, i32 0, i32 %adj
store i32 200, i32* %gep
```

For `int[5] arr` (startIndex = 0) the adjustment is skipped (no `sub`).

### Printing all elements (compile-time unrolling)

Instead of emitting an LLVM loop (which would need phi + branches), printing is
unrolled at compile time:

```llvm
; print arr  (int[3] arr)
%1 = getelementptr inbounds [3 x i32], [3 x i32]* %arr, i32 0, i32 0
%2 = load i32, i32* %1
%3 = call i32 @printf(@fmt_i32_p, i32 %2)
%4 = getelementptr inbounds [3 x i32], [3 x i32]* %arr, i32 0, i32 1
%5 = load i32, i32* %4
%6 = call i32 @printf(@fmt_i32_p, i32 %5)
; ... (for every element)
```

### String variables

A string uses two allocations: a pointer and a buffer.

```llvm
%s     = alloca i8*              ; pointer to the current string
%s_buf = alloca [256 x i8]       ; buffer for up to 255 chars + '\0'
%1     = getelementptr inbounds [256 x i8], [256 x i8]* %s_buf, i32 0, i32 0
store i8* %1, i8** %s            ; pointer set to the buffer
```

String assignment uses `strcpy` instead of copying the pointer:
```llvm
%buf = getelementptr inbounds [256 x i8], [256 x i8]* %s_buf, i32 0, i32 0
%r   = call i8* @strcpy(i8* %buf, i8* %src)
; %r is unused but MUST get a register number (LLVM SSA)
```

## 10. Error handling

Compiler diagnostics are printed in Polish.

### Lexical and syntax errors

Detected by ANTLR and captured by `ErrorListener`.
Compilation stops before semantic analysis.

```
Blad skladniowy [linia 3:7]: nieoczekiwany token 'xyz'

Kompilacja przerwana.
```
(`Syntax error [line 3:7]: unexpected token 'xyz'` / `Compilation aborted.`)

### Semantic errors

Detected by `LLVMActions` while walking the tree.
All errors are collected and reported; no IR is generated.

```
Blad semantyczny, linia 5: warunek if musi byc bool

Kompilacja przerwana.
```
(`Semantic error, line 5: if condition must be bool`)

Checked error kinds:
- Use of an undeclared variable, array or function
- Duplicate declaration
- Type mismatch in assignment or initialization
- Arithmetic or logical operations on unsupported types
- Non-bool conditions in `if` / `while`
- Illegal casts
- Invalid array range (start > end)

## 11. End-to-end example

### Source (MyLang)

```
int x = 5
int y = 3
bool big = x > y
print big
```

### Generated LLVM IR

```llvm
declare i32 @printf(i8*, ...)
declare i32 @__isoc99_scanf(i8*, ...)
declare i8* @strcpy(i8*, i8*)

; ── Format strings ───────────────────────────────────────────────
@fmt_i32_p = constant [4 x i8] c"%d\0A\00"
...

; ── Program body ─────────────────────────────────────────────────
define i32 @main() nounwind {
  ; int x = 5
  %x = alloca i32
  store i32 5, i32* %x

  ; int y = 3
  %y = alloca i32
  store i32 3, i32* %y

  ; bool big = x > y
  %big = alloca i1
  %1 = load i32, i32* %x
  %2 = load i32, i32* %y
  %3 = icmp sgt i32 %1, %2     ; signed greater-than
  store i1 %3, i1* %big

  ; print big
  %4 = load i1, i1* %big
  %5 = zext i1 %4 to i32        ; bool → int for printf
  %6 = call i32 (i8*, ...) @printf(
         i8* getelementptr inbounds ([4 x i8], [4 x i8]* @fmt_i32_p, i32 0, i32 0),
         i32 %5)

  ret i32 0
}
```

### Program output

```
1
```
